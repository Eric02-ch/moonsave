# v0.2 私人同步與資料搬移

## 使用方式

1. 開啟 README 的私人雲端版網址，用建立此 Site 的同一個 ChatGPT 帳號登入。
2. 如果舊資料在 GitHub Pages，本機版的「目標與備份」可匯出含草稿 JSON。備份含財務資料，請勿提交至 GitHub。
3. 到私人雲端版「目標與備份」選擇匯入；確認後，回報、目標與草稿會同步到目前登入帳號。
4. Chrome 或手機使用同一個私人雲端網址、登入同一帳號，就能載入相同資料。請勿繼續把 GitHub Pages 本機版當成雲端版。
5. 儲存資料後等待上方顯示「已與雲端同步」，再切換裝置。

GitHub Pages 是本機展示版，不支援登入或資料庫；它會提供私人雲端版連結。舊資料不會因網站程式更新而自動離開本機。

## 同步規則

- 儲存回報、目標或草稿後，約一秒內排程上傳。
- 另一次變更發生於請求途中時，保留未送出的變更，再送下一版。
- 每 20 秒、回到分頁及重新連線時檢查同步；表單尚有未儲存輸入時，不用遠端版本覆蓋畫面。
- 每個帳號一份快照，包含回報、目標與一份待確認草稿。
- 使用資料庫原子版本比對；版本落後會回覆 409，不採用最後寫入者直接覆蓋。
- 發生衝突時，先匯出本機備份，再選擇載入雲端版本並手動整理。沒有偷偷強制覆寫的按鈕。
- 同步版本與本機快取依帳號區分；請求也攜帶預期帳號，避免其他分頁切換帳號後誤把舊快取寫入新帳號。
- 離線時保留本機變更，重新連線後重試。首次登入及冷啟動讀取身分需要網路。

## 隱私與範圍

私人版目前僅允許 Site 擁有者瀏覽。Sites 提供登入與網站存取邊界，API 另外使用登入 user ID 查詢資料庫，拒絕未登入、跨站寫入、格式錯誤及超量請求。

這不是端對端加密；雲端服務會處理你主動匯入或儲存的資料。公開原始碼裡只有資料結構與程式，沒有私人 D1 資料列、實際財務備份、登入憑證或真實財務畫面截圖。

## 驗證

原有 13 項計算與資料驗證，加上 5 項同步測試全部通過。同步測試使用記憶體 SQLite 驗證實際 SQL：帳號隔離、帳號切換、跨站請求、版本競爭、草稿 null 值與資料大小限制。

本機整合測試使用不同 origin 的獨立瀏覽器儲存空間，透過同一個開發登入帳號與 D1 讀到同一份正式回報與部分草稿；測試資料均為虛構數字。
