# MoonSave v0.1 產品決策

## 使用者需求

以每月回報取代聊天中散落的財務數字；輸入方式適合手機、有累積感，並保留 AI 回顧與追問的可能。作品同時用於練習 GitHub 和展示產品思考與開發能力。

## 第一版取捨

1. **月回報優先**：沿用先存後花、不逐筆記帳的習慣。先提供資金分區與儲蓄流入／提領；日後加分類支出與對帳。
2. **每次確認數字**：帳戶分類固定，但不自動繼承上月餘額。日期與確認勾選能減少將規劃值誤認為實際值的問題。
3. **程式計算、助手解釋**：金額由可測試的純函式產生；AI 不負責記帳帳本或改寫紀錄。
4. **本機優先**：不用帳號即可試用；備份由使用者帶走。也接受暫時沒有雲端同步的限制。
5. **如實標示 AI**：未連接模型時顯示本機規則月報，避免讓固定文字看起來像已執行 AI 分析。
6. **成長而非懲罰**：花園跟隨實際備用金達成率，不以連續打卡、扣分或負面訊息對待單月起伏。
7. **暫不評財務等級**：尚未掌握完整資產、負債及支出，不產生看似精準的 A～D 評分。

## 成功標準

能在手機版完成一個月回報、看懂儲蓄與預留款差異、修改紀錄，並在重新開啟後找到資料；能匯出備份並還原。

## 待觀察問題

- 每月十一個金額欄位是否負擔過高？
- 使用者是否能正確區分「既有資金轉移」與「本期新增儲蓄」？
- 當儲蓄提領源自過去收入時，是否需要更完整的期間與提領註記？
- 是否應在第二版加入帳戶餘額勾稽，以提示回報不一致，而非直接給出財務評價？
