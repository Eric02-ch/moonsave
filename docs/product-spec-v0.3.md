## 1. 產品目的

讓使用者依薪資週期回報收入、支出與帳戶餘額，在手機上快速看懂目前資金、本期收支、儲蓄目標與歷史變化。回報應簡單，資料可持續累積，並可在需要時主動取得 AI 建議。

第一版先服務個人實際使用，並保留可公開分享的作品體驗版。

## 4. 統計期間與回報方式

### 4.1 薪資週期

**建議細節：**使用者第一次設定固定發薪日，之後自動產生週期。

例：發薪日為每月 10 日。

| 週期標籤 | 起日 | 迄日 |
| --- | --- | --- |
| 2026 年 11 月 | 2026-11-10 | 2026-12-09 |
| 2026 年 12 月 | 2026-12-10 | 2027-01-09 |

- 週期依開始發薪日所在的年月命名。
- 每次進入回報頁，預設顯示最近剛結束的薪資週期；可切換至其他週期補填或編輯。
- 首頁及回報頁以短標籤顯示週期範圍，方便理解。
- 使用者能切換舊週期，修改或補填月回報。
- 報表建立、修改時間由系統記錄，無須手選每日日期。
- 進行中週期的數字標示「截至目前」；不預估尚未發生的收入或支出。
- 回填已結束週期時，帳戶欄位應填該週期結束時的餘額。

**已確認的結算流程範例：**假設每月 10 日發薪，11/10 開啟 App 時，優先結算 10/10～11/9 的週期（依開始年月標為「2026 年 10 月」）。收入與支出都對應這段期間，11/10 新入帳的薪資歸入下一期。帳戶餘額對應 11/9 期末值；可直接填寫，或依 4.4 使用目前餘額經確認後回推。

首頁必須同時顯示週期標籤與簡短範圍，例如「10 月週期 · 10/10–11/9」，避免在 11/10 回報時誤以為月份標示錯誤。

**發薪日的首頁行為（已確認）：**11/10 開始 11/10～12/9 的新週期，當天薪資只歸新一期；首頁提供 10/10～11/9 的上一期總結評價。介面要明確區分「新週期」與「上一期總結」。

- 上一期總結使用上一期已提供的收入、支出及對應資料，不讀入新一期薪資。
- 如果上一期資料尚未填齊，顯示補齊回報入口及可用摘要；不自動取得銀行資料，也不捏造完整評價。
- 「總結評價」的具體形式（簡短文字、目標狀態或分數／等級）尚待確認。
- 帳戶餘額須標明觀察時間與來源：發薪後當下餘額不能直接標成上一期期末值，回推條件見 4.4。

### 4.2 邊界條件

- 跨年度週期需要正確計算。
- 建議發薪日可選 1～31 日，短月份沒有該日則使用該月最後一天。
- 已儲存回報保留當時週期範圍；設定變更不得重新解讀歷史回報。
- 提前或延後發薪、發薪日變更的處理方式，列入待確認細節，不自行把假設當成已完成規則。

### 4.3 三種日期各自的用途

| 設定 | 用途 | 與回報週期的關係 |
| --- | --- | --- |
| 發薪日 | 決定薪資週期的起訖與優先結算哪一期。 | 作為收入、支出總額的期間基準。 |
| 信用卡結帳日 | 顯示信用卡帳單結算時間。 | 帳單期間獨立，不改變薪資週期。 |
| 信用卡繳款日 | 顯示卡費繳款時間，協助預留資金。 | 繳款時不再次列入已計過的消費支出。 |

- 本文「週期最後一天」指下次發薪日前一天；例如發薪日 10 日，10/10～11/9 的最後一天是 11/9。
- 建議信用卡日期依卡片分別設定，支援不同卡片不同結帳日與繳款日；是否同版支援多張卡仍需確認。
- 建議以結帳後下一個設定繳款日作為日期推算起點；跨月、假日及特殊帳單以實際帳單資訊校正，不宣稱系統推算就是銀行確認日期。
- 第一版日期設定與顯示範圍，不自動取得銀行帳單、推算應繳金額或啟用系統推播。
- 結帳日、繳款日通常與薪資週期不同，整張信用卡帳單總額不能直接當作同一薪資週期的支出。
- 回報畫面不要求每次重新填三種每日日期，沿用使用者設定。

### 4.4 期末餘額與目前餘額

回報提供「上期期末餘額」及「目前餘額」兩種方式，沿用同一套薪資週期，不增加每日日期選擇器。

- 上期期末餘額：使用者確認數字對應週期最後一天結束時，直接作為期末快照。
- 目前餘額：系統記錄盤點時間，請使用者確認從上期結束至盤點當下的新一期變動；包含新薪資、其他入帳、消費、退款、投資移轉、卡費繳款等，不可只扣新薪資。
- 回推逐帳戶處理：上期期末餘額 = 目前餘額 − 新一期該帳戶的有號餘額變動。資產及負債分別保留變動方向，例如繳卡費會使銀行及卡債餘額都下降；同一筆轉帳對應兩個帳戶。
- 回推調整屬於新一期的橋接資料，不列入上一期收入、支出或第 6.2 節的特殊調整，避免重複計算。它也不代表已完成新一期回報。
- 確認頁同時呈現目前值、調整及回推期末值，只有使用者確認變動完整後才能採用。回推值保留來源標記，不改稱直接取得的實際期末值。
- 無法完整確認變動時，可保留目前盤點及草稿，不推估上期支出。若另有上期實際支出，可呈現該期收支，但不能把目前餘額標成該期期末值或用作後期推估基準。
- 此流程是回報時的簡短輔助調整，不擴充成每日交易帳本。盤點時間跨越多個週期且無法可靠橋接時，改補期末值或實際支出。

## 5. 頁面規格

### 5.1 Dashboard

首頁回答以下問題：目前有多少、本期收入多少、支出多少、結餘多少、儲蓄目標進度如何、過去如何變化。

**建議排列：**

1. 週期名稱與切換入口。
2. 四張數據卡：本期收入、本期支出、本期結餘、帳戶淨額。
3. 儲蓄目標與進度。
4. 歷史趨勢：可切換資金走勢與收支走勢，避免堆疊多張圖。
5. 帳戶餘額摘要。
6. 月度紀錄清單，點擊即可編輯該期回報。

主要操作：更新本期回報。次要操作：AI 建議。

發薪日需提供上一期總結入口；若首頁同時呈現目前帳戶狀況與上一期收支，兩個區塊分別標示時間範圍，不混算。

狀態規則：

- 首次使用引導建立固定盤點清單；起始盤點完成後顯示帳戶分布及目標進度，說明需累積下一個可比較期末才能推估支出。
- 有草稿時，顯示待完成狀態並可繼續填寫。
- 缺少必要數字時，相關數據卡顯示「—」或「待補齊」。
- 沒有上期資料時，不顯示變化百分比。
- 成長紀錄留在首頁，底部導覽不再提供獨立入口。
- 示範資料必須可辨識為虛構，不能混入私人實際回報。

### 5.2 月回報

預設為最近剛結束的薪資週期。使用者可直接開始結算，不必先選每日日期。先填收入與帳戶盤點，由系統協助推估支出；也可使用既有記帳或銀行資料的同週期實際支出總額。

| 區塊 | 輸入內容 | 規則 |
| --- | --- | --- |
| 本期收支 | 收入總額、推估或實際支出 | 統計同一薪資週期；推估條件與限制見 6.2。 |
| 帳戶餘額 | 使用者已設定的各帳戶餘額 | 沿用帳戶清單，不沿用舊餘額作為本期已確認數字。 |
| 特殊資金變動 | 選填投資轉出、非收入轉入或其他調整及原因 | 僅填影響盤點範圍、但不屬於收入或消費的變動；同範圍帳戶間轉帳不需填。 |
| 備註 | 選填短文字 | 預設收起，避免長文字占據表單。 |
| 確認與儲存 | 存草稿、下一步：確認資料 | 草稿允許缺漏；確認頁列出週期、收支、支出來源、調整及帳戶餘額，可返回修改；最後按「確認儲存」才正式寫入回報。 |

確認頁須明確詢問推估是否符合實際，不能預先勾選為已確認。返回修改收入、餘額或調整後，舊推估確認失效，須重新確認。正式儲存失敗時保留輸入，顯示重試；雲端尚未同步時不宣稱已完成雲端儲存。

收入先以總額作為建議介面；是否保留薪資與其他收入的選填拆分，仍待確認。

移除的輸入：每日盤點日期、基本儲蓄、額外儲蓄、從儲蓄提領使用。

### 5.3 自訂帳戶

帳戶管理放在回報頁的次要入口，不占用獨立導覽頁。首次建立固定盤點清單，讓使用者選取實際使用的銀行、儲蓄、現金、電子錢包及信用卡，不強迫建立不存在的帳戶；每期沿用並簡短確認是否漏項。資產來源與用途類別分開，不因「電子錢包」而重複計算同一筆錢。

**建議欄位：**

| 欄位 | 用途 |
| --- | --- |
| 帳戶名稱 | 使用者自行命名。 |
| 類別 | 日常、儲蓄、專用款、信用卡欠款。 |
| 使用狀態 | 用於本期回報，或封存。 |

行為：

- 可新增、改名、調整類別及封存帳戶。
- 每個帳戶使用穩定識別碼，名稱不是資料關聯依據。
- 歷史回報保留當時帳戶名稱、類別與餘額快照。
- 封存帳戶不會刪除歷史金額。
- 新增帳戶的本期餘額留白，填 0 才代表確認沒有餘額。
- 同一筆錢不可重複存在兩個帳戶金額中。
- 帳戶類別選項與預設帳戶數量仍可在下一輪線框圖討論中調整。

### 5.4 AI 建議

**本次交付：**僅保留 Dashboard 小按鍵，點擊後清楚顯示「AI 建議尚未啟用」；不送出財務資料，不呼叫模型。下列分析行為為後續版本規格，不列入本次完成條件。

- Dashboard 上提供一個小按鍵。
- 完整報告畫面包含收支、較上期變化、帳戶變化與 AI 建議區；首頁按鍵可直接進入該區。真實 AI 未啟用前，顯示未啟用狀態，數據報告仍可閱讀。
- 使用本期與最近最多三期的已提供資料。
- 回覆包含簡短觀察與最多三項行動建議。
- 計算由程式完成；AI 解釋已計算數字及趨勢。
- 缺少資料時明確指出，不補造收入、支出、餘額或儲蓄率。
- 當期仍在進行時，說明這是目前累計數字。
- 首次使用前說明資料會傳送給 AI 服務並取得同意。
- 不在背景自動送出財務資料或產生付費分析。
- 必須有載入、成功、失敗、資料不足及尚未啟用狀態。
- 固定規則摘要不能標示為已取得 AI 分析。

**後續啟用條件：**正式環境目前沒有啟用付費模型；後續再確認模型服務、金鑰管理及使用預算，不阻擋本次核心版交付。

### 5.5 設定

保留必要項目，長說明收在按需展開的區塊。

- 薪資週期設定：首次設定發薪日。
- 信用卡日期：設定結帳日、繳款日，與發薪日分開。
- 儲蓄目標：v1 僅一個目標，包含名稱、正數目標金額及一個指定資產帳戶，可修改。進度採最近有效盤點的指定帳戶餘額，標示資料時間；提領後進度下降。金額可超過目標，進度條最多填滿，數字仍顯示實際值。無有效餘額時顯示待補資料；封存目標帳戶時要求改綁或暫停目標，不抹除歷史回報。
- 資料備份：匯出、匯入，包含草稿。
- 私人版：登入身分、同步狀態、重試、登出。
- 不提供未定義的「進階設定」。同步衝突在發生時提供處理入口；清除體驗資料若提供，放在資料管理內並明確確認。

首頁、表單與設定頁不放技術架構、API 設定、GitHub 或資料庫教學；這些留在 README。

### 5.6 推估調整與回報維護

- 推估確認頁提供「轉去投資」「退款或非收入轉入」「借款相關」「其他」等原因選項，填金額及必要說明，由系統轉為第 6.2 節的有號調整。選到已反映於追蹤帳戶的轉帳或借款時，不重複調整。
- 退款如已反映於實際支出淨額，不再次扣減；推估時可選擇按消費沖減處理，或明確指定為本期非消費轉入。資料不足時不自動猜分類，保留修改或改填實際支出的入口。
- 同一使用者、同一週期僅一份正式回報。編輯仍須經確認頁，儲存成功才取代原版，重複點擊不新增另一份；取消或失敗保留原正式回報與修改草稿。
- 刪除前顯示週期與影響，確認後才刪除。若該期是後期推估依據，後期標記待重新確認，缺少有效期初時停用推估；手填實際支出不被改寫。
- 修改或刪除引發的影響需沿依賴關係檢查。受影響舊值可留在明細，但不繼續當成有效已確認指標。

### 5.7 下期行動

完整報告提供一個選填短文字欄位「下期想改善的一件事」，不阻擋回報完成、不自動產生 AI 建議。下次回報帶出最近一筆適用於該期的行動，可選填完成／未完成／略過及簡短心得，再設定下一期行動。未回應不當作失敗，不做連續打卡、評分或推播。歷史報告保留當時行動及回顧，不被新行動覆蓋。

### 5.8 報告與同步狀態

狀態分開保存及呈現，不把「已確認」當成「實際支出」或「已同步」：

| 維度 | 狀態與行為 |
| --- | --- |
| 回報完整度 | 起始盤點／待補資料／完整回報；起始盤點可正式保存，仍不能推估首期支出。 |
| 支出來源 | 未知／實際／推估；推估確認後仍顯示「含推估」。 |
| 確認狀態 | 未確認／已確認／待重新確認；依據變動會撤銷原推估的有效確認。 |
| 儲存同步 | 尚未儲存／已存本機、待同步／同步中／已同步／同步失敗或衝突；公開體驗版標示僅存此瀏覽器。 |

首頁只顯示當下最需要處理的狀態，詳細來源放完整報告；不能用一個「完成」標籤掩蓋資料缺漏或同步失敗。

## 6. 指標與計算定義

| 指標 | 定義 | 顯示條件 |
| --- | --- | --- |
| 本期收入 | 同一薪資週期實際入帳的收入總額 | 收入欄位已提供。 |
| 本期支出 | 使用者填入的實際總額，或確認過的系統推估值 | 顯示「實際支出」或「推估支出」；未確認推估不作為正式報告數字。 |
| 本期結餘 | 本期收入－本期支出 | 兩者都有數字；可為負。 |
| 帳戶資產 | 日常、儲蓄與專用款帳戶餘額加總 | 納入的資產帳戶都填齊。 |
| 帳戶負債 | 信用卡欠款類別加總 | 納入的負債帳戶都填齊。 |
| 帳戶淨額 | 帳戶資產－帳戶負債 | 相關帳戶數字完整。 |
| 日常餘額 | 日常類帳戶加總 | 日常帳戶都填齊。 |
| 儲蓄累積 | 單一目標指定資產帳戶的餘額 | 指定帳戶已有有效盤點值。 |
| 目標進度 | 儲蓄累積 ÷ 目標金額 | 目標有效且指定帳戶已填齊。 |
| 帳戶月變化 | 本期帳戶淨額－上期帳戶淨額 | 連續兩期都有完整資料。 |

### 6.1 收支與帳戶盤點的規則

- 本期結餘與帳戶月變化各自呈現，不要求兩者一定相等。
- 投資轉出、帳戶範圍改變或其他資金移動，可能影響帳戶月變化；不能直接把變化解讀成消費或新儲蓄。
- 自己帳戶間轉帳不列為收入或支出。
- 信用卡消費發生時列入該期支出；繳卡費時不重複列支出。
- 信用卡預留款列在資產帳戶，信用卡未繳金額列在負債帳戶。
- 未入帳的獎金、規劃中的兼職收入不納入實際收入。
- 第一版不顯示完整淨資產或投資報酬，因為沒有納入完整資產、負債與投資資料。
- Dashboard 使用「本期結餘」名稱；若後續加入儲蓄率，需另行定義並確認，這版不先加。
- 過往回報沒有支出總額時，該欄留白，不由舊餘額推算成實際支出。

### 6.2 支出推估與確認（本輪已確認方向）

推估採相同盤點範圍、連續薪資週期的期初與期末帳戶淨額，信用卡未繳金額須包含已發生但尚未繳清的消費，不能僅使用最近一期帳單應繳額。信用卡日期本身無法提供未繳金額。

定義：

- 帳戶淨額 N = 納入盤點的資產餘額合計 − 納入盤點的負債餘額合計。
- 淨額變化 ΔN = 期末 N − 期初 N。
- 調整 F = 非收入、非消費而流入盤點範圍的金額 − 流出該範圍的金額。
- 推估支出 = 本期收入 + F − ΔN。

範例：收入 40,000，淨額增加 5,000，另有 10,000 轉到未納入盤點的投資帳戶，F = −10,000，推估支出為 25,000。同一筆投資轉出不可同時列為支出及調整。

實作與驗收規則：

- 第一次回報建立基準，不憑單次餘額推算支出。可填實際支出完成回報；無法取得時存基準紀錄，支出與結餘保持未知，不補 0。
- 缺少連續上期資料、帳戶餘額不完整、盤點時間不符或帳戶範圍不可比較時，不提供可確認的推估。使用者可補齊資料或改填實際支出。
- 新增、封存或漏填帳戶不得當成消費或儲蓄。只有能建立相同範圍的期初與期末比較時才恢復推估；舊帳戶改名不影響範圍。
- 帳戶間轉帳、以盤點中的銀行帳戶繳盤點中的信用卡，不另填調整，也不再次列消費。
- 非收入轉入、未追蹤投資轉出、未追蹤借款等僅在確實影響盤點範圍時調整；已反映於追蹤負債的借款不得重複調整。不提供完整借貸管理。
- 投資行情、匯率或其他非收支估值變動不能當成消費；若使用者無法分離變動，改填實際支出，不宣稱推估可靠。
- 推估為負數時不截成 0、不允許直接確認；提示檢查收入、餘額與特殊變動，或改填非負的實際支出。
- 推估值顯示來源與計算明細，使用者可調整特殊變動或直接填實際支出。手填實際支出不會在修改帳戶後被靜默覆寫。
- 推估確認僅表示使用者接受該估值，不改標為實際支出；本期結餘與比較沿用其來源標示，不能宣稱等於實際新增存款。
- 修改前期餘額可能影響後期推估；標記受影響回報待重新確認，不靜默改寫已儲存的後期支出。
- 盤點時間沿用第 4 節：11/10 新薪資不得混入 11/9 期末餘額；目前餘額僅能經第 4.4 節完整橋接與確認後回推，無可靠期末值時不推估。

### 6.3 完整報告與摘要

首頁優先呈現「這期留下多少」「比上期多／少留下多少」及支出增減，並標明週期與推估來源。完整報告呈現收入、支出、結餘、帳戶淨額變化、特殊調整及比較依據。沒有可比較資料時不顯示增減；任一期採推估時，比較也標示含推估。AI 後續只解讀程式算好的數字，不代算或補造支出。

- 保留目前已有的回報、11 月草稿、目標與來源備註。

- 新增的支出欄位預設未知，不補 0，也不以模型猜測。
- 舊月份如何對應新的薪資週期，需要使用者確認；不假設舊月報已符合新週期定義。
- 匯出備份需能帶走舊資料與新欄位，支援還原。
- 新舊客戶端同時開啟時，落後版本不得覆蓋已更新的資料。
